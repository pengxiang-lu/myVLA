# myVLA 模型历史

## 一、VLA框架：

- 输入：224×224 双相机 RGB 图像、任务语言、8 维机器人状态。
- 视觉编码器：预训练 CLIP ViT-B/16，V1/V1.1/V1.2 冻结，V2/V2.1/V2.2/V2.3 参与训练；V3.1 换用 SigLIP，详见下文。
- 文本编码器：CLIP 文本编码器，所有版本均保持冻结。
- 输出：当前各版本训练配置均为 `chunk_size: 12`，输出 12×7 动作块。
- 损失函数：前 6 维 Smooth L1，夹爪 BCE；排除轨迹尾部 padding。

## 二、V1、V2六个版本对比

​	V1 系列（V1、V1.1、V1.2）冻结 CLIP 视觉编码器；V2 系列（V2、V2.1、V2.2）训练视觉编码器。每个系列分别提供 0、2、6 层双向视觉—语言交叉注意力融合块。文本编码器在六个版本中均冻结。

​	六个版本均使用 4 层动作解码器，预测 12×7 动作块。表中融合块位于动作解码器之前，融合块层数不包含动作解码器内部的注意力层。无额外融合块的版本仍通过动作解码器读取多模态 memory。

### 配置与训练目录

​	六个版本的默认训练设置一致：使用全部训练数据、不划分验证集；batch=16、梯度累积=4（有效 batch=64），训练 10,000 步，500 步 warmup，权重衰减 `0.001`，EMA 衰减 `0.999`，每 2,000 步保存 checkpoint。训练期间不计算验证 loss，不启动定期仿真评估。历史训练的实际设置以对应 checkpoint 中的配置为准。

## V3—Flow Matching 动作头

​	V3 基于 V2.2，保留可训练 CLIP 视觉编码器、冻结文本编码器、6 层双向视觉—语言融合以及 4 层 Transformer 动作解码器。区别在于解码器接收带噪动作和时间嵌入，输出动作速度场，替代直接回归动作。

## V3.1：SigLIP 编码器 + V2.2 回归动作头

​	V3.1 将 V2.2 的 CLIP 视觉和文本编码器替换为 `google/siglip-base-patch16-224`，保留 6 层双向融合、4 层动作解码器、12 步动作块及原有 Smooth L1 + 夹爪 BCE 损失。视觉编码器继续训练（`1e-5`），文本编码器冻结，融合和动作头学习率为 `1e-4`；单套件及联合训练配置分别沿用对应 V2.2 的训练参数。

​	适配内容包括：保留 SigLIP 全部 196 个视觉 patch（没有 CLS），文本固定 padding/truncation 到 64 token，不对固定 padding 加 attention mask，使用模型原生文本 pooled output。融合摘要继续使用最后一个 token 的交互残差；SigLIP 的该 token 是固定序列末尾 token。数据与增强接口沿用 CLIP 图像规范，编码器内部先还原 RGB，再转成 SigLIP 的 mean/std=0.5 规范，保证训练、闭环评估及耗时测量一致。


## V3.2：SigLIP 编码器 + Flow Matching 动作头

​	V3.2 组合 V3.1 的 SigLIP Base patch16-224 视觉/文本编码器和 V3 的条件 Flow Matching 动作头。沿用 6 层双向视觉—语言融合、4 层 Transformer 动作解码器和 12 步动作块；视觉编码器参与训练（学习率 `1e-5`），文本编码器冻结，融合模块和动作头使用 `1e-4`。

| 模型 | 编码器 | 动作头 |
|---|---|---|
| V2.2 | CLIP | 直接回归 |
| V3 | CLIP | Flow Matching |
| V3.1 | SigLIP | 直接回归 |
| V3.2 | SigLIP | Flow Matching |
| V3.3 | CLIP | Diffusion（噪声预测 + DDIM） |

## V3.3：CLIP 编码器 + Diffusion 动作头

​	V3.3 基于 V2.2，保留可训练 CLIP 视觉编码器、冻结文本编码器、6 层双向视觉—语言融合、4 层 Transformer 动作解码器及 12 步动作块。动作查询加入带噪动作投影和时间嵌入，解码器预测噪声，而不是直接回归动作或预测 Flow Matching 速度场。

​	训练采用余弦 DDPM 噪声调度，默认 `diffusion_train_steps: 100`，随机抽取时间步，按 `x_t = sqrt(alpha_bar_t) * x_0 + sqrt(1-alpha_bar_t) * noise` 加噪，使用有效动作步上的噪声预测 MSE。LIBERO 前 6 维沿用原有均值/标准差归一化，夹爪由 `{0,1}` 映射至 `{-1,+1}` 后共同扩散；MT50 四维动作均按连续量处理。轨迹末尾 padding 不计入损失。

​	推理从高斯噪声出发，默认 `diffusion_inference_steps: 10`，使用 DDIM（`eta=0`）逐步去噪。标准化动作不在采样过程中裁剪至 `[-1,1]`；输出沿用现有反归一化、夹爪符号判定及环境动作范围裁剪。更大的采样步数会增加推理开销，效果需实测。

​	单套件与四套件配置分别为 `configs/libero_spatial/train_cfg_v3_3.yaml`、`configs/libero_all/train_cfg_v3_3.yaml`。训练参数对齐对应 V2.2：单套件有效 batch=64、10,000 步；四套件有效 batch=64、40,000 步。当前仅完成代码与离线测试，尚未训练或评估闭环成功率。实现采用条件动作扩散思路，保留本项目原有编码器和归一化方案，不是对 [Diffusion Policy](https://diffusion-policy.cs.columbia.edu/) 完整架构的复现。

## 附录：结论

### 数据集验证集划分

​	一开始我是将训练数据集分为90%训练和10%固定验证集，在800固定验证帧上计算loss来作为验证集结果。但是发现按照验证loss选择出的best.pt权重在任务完成上成功率还不如继续训练的。

​	后来我直接不划分训练集和验证集，全部数据用于训练，发现任务成功率会替身大约5%百分点。

### 输出步长

​	需要注意训练的时候要按什么action_chunk大小来训练，评估的时候如果action_chunk小于训练的action_chunk，会截取训练action_chunk的前面部分来作为动作。
